# Design tokens split into three tiers, derive from per-ColorScheme anchors, and expose a manifest-declared contract

The token layer gains **three tiers**: a **Palette** of **8 anchor colours plus 3 numeric knobs** per **ColorScheme** (tier 1, private), the semantic roles the UI styles itself from (tier 2, public), and a plugin's own domain vocabulary (tier 3, owned by that plugin). Tier 2 ships as a **derivation** of tier 1 rather than as literals, so re-theming Hexly is a **12-value job per ColorScheme instead of 35**. The derivation runs **in CSS** — relative colour syntax, `color-mix()`, `contrast-color()` — and a **manifest** declares which tokens are public, of what type, so one artifact generates the `@property` registrations, the lint allowlist, the `DesignToken` union, and the theme editor's controls.

The anchor and knob counts, the per-token expressions, and the exception list are not estimates: they were fitted numerically against the shipped values and are recorded in [`docs/design/spike-token-derivation.md`](../design/spike-token-derivation.md) and [`docs/design/spike-tone-rotation.md`](../design/spike-tone-rotation.md).

This **amends ADR-0020's mechanism** (how the tokens are declared and where they live) and does not reopen ADR-0007 or ADR-0021: primitives still own their scoped styles, and elevation is still raw vars wrapped in a custom `@utility`. It exists to make ADR-0076's **World Theme** possible; without that feature it would not be worth the churn, and that is the honest justification for the size of it.

## What forced it

`tokens.css` and the `@theme` block declared **44 colour tokens**, with **46** reassigned under `[data-theme='dark']`. `docs/design/identity.md` claims the set is semantic — _"Tokens are named by role, themed by value"_ — but the roles are spelled as hues, and the gap shows up as bugs rather than as untidiness:

- **`--color-gold-deep` is documented as "deep stop of the gilded gradient"** and used as **heading ink** in eight places across `plugin-draw-steel-web` (`traits-section`, `stat-block-view`, `abilities-section`). Rebalancing the metallic gradient's stops silently recolours Draw Steel's stat blocks.
- **`--color-on-gold`'s only consumer, anywhere, is `button.component.ts`'s `.is-danger:hover` foreground** — a token named for gold that exists to sit on ember.
- **`--color-sea` and `--color-astra` are not a secondary and tertiary accent.** Their consumers are `chip.component.ts`'s `ChipTone` typed input and the `graphColorToken` maps in `dnd-types.ts`, `content-types.ts`, `asset-types.ts`, `hexmap-types.ts` — a categorical palette whose only job is mutual distinguishability. `dnd-types.ts:29` already carries a comment explaining which role a hue-named token plays, which is the tell.
- **`--color-terrain-marsh` was dead** — declared in both schemes and rendered in the styleguide, but absent from `terrainPalette`.
- **36% of the "semantic" tier was plugin-domain colour** (`terrain-*`, `canvas-*`, `hex-line`, `feature-ink`, `label-ink`, `name-ink`, `ink-stroke`) declared in core `web-styles`, a leaf lib the consuming plugins do not own.

What the measurements then showed was the opposite of what we expected, and it is the reason this is worth doing at all: **Solar and Astral are mirror images of each other, and nobody designed that deliberately.** The ink ramp spans +0.372 OKLab-L in Solar and −0.375 in Astral; the paper ramp's chroma-vs-lightness slope is −0.42 and +0.42; `gold-deep`'s offset from `gold` is ±0.0865. A single ±1 polarity knob carries all of it, and fifteen tokens ride that knob with one coefficient each — a real constraint the hand-tuned values had to satisfy, and did. The symmetry fell out of tuning each scheme until it "felt equivalent"; asserting it in the tokens is cheaper than re-deriving it by hand every time a colour moves.

(An earlier reading of the same data claimed the two ramps had incompatible _shapes_ — a 1.38× luminance span against 5.9×. That was an artefact of measuring in linear luminance, which OKLab's L is roughly the cube root of; the perceptual spans are 0.101 and 0.106. The real difference is where each ramp puts its energy — Solar hangs 87% of its range below `surface`, Astral puts 40% above it — which the polarity knob absorbs at ΔE00 ≤ 1.13 without a dedicated spread knob.)

## Considered Options

- **Rename the hue-named roles and stop there (one flat tier).** Rejected. It buys legibility and not one value of authoring surface: each of the 44 tokens still carries an independent literal, and there is still no way to say "make this world crimson" in one move.
- **Explicit ramps in tier 1 (~15 entries per scheme).** Rejected as the wrong point on the curve: full fidelity, but ~30 values to author is still large enough that a custom theme is a project rather than an afternoon.
- **A knob per token, used affinely.** Rejected, and this is the trap the whole exercise had to be defended against. With only two schemes to fit, any expression carrying a scale _and_ an offset hits both targets exactly — a 2×N matrix always has rank ≤ 2 — so its ΔE00 of 0.00 is information-free. The sharpest case: `ink-muted` needs hue 80° in Solar and 278° in Astral, and `calc(h + 95 - 96*var(--tone))` derives it at ΔE00 0.48, a beautiful number that means nothing because 95 and −96 _are_ the two literals. That is an `if()` in disguise, and every token is judged by how constrained its expression is, not by its error.
- **Derive in TypeScript instead of CSS.** Rejected once `getComputedStyle` was understood to return the _used_ value for **registered** custom properties (CSSWG issue #10371), so TS can read the browser's own resolved colours rather than recomputing them. The TS route would have meant a second implementation of the ramp maths — one for rendering, one for the contrast report — that will drift. It also loses free tier-2 overrides and leaves devtools showing flat literals instead of live relationships.
- **Keep hue names for the categorical set.** Rejected by the same test that condemned `--color-gold`: an Owner who sets `--color-sea` to purple gets the identical lie.

## Decision

- **Tier 1 — Palette.** **Eight anchors per ColorScheme** — page, ink, quiet ink, accent, danger, success, canvas, and soot (shadow/scrim ink) — each carrying its own hue, which is how the Solar→Astral hue rotation is expressed. Quiet ink is a separate anchor precisely because that rotation is otherwise unreachable: derived off the primary ink anchor with any fixed hue offset, `ink-muted` collapses to grey (ΔE00 15.8/15.3). Plus **three knobs**, registered as `<number>`: `--tone` (±1 scheme polarity — the mirror-symmetry finding, and the only one that is a genuine discovery), `--line-alpha`, and `--veil`. Named `--palette-*`, private by manifest **and** by convention. (**Amended in implementation (#366):** the polarity knob ships as `--palette-polarity`, not `--palette-tone`, so it cannot be read as one of the categorical `--color-tone-*`.)
- **Tier 2 — semantic roles**, declared as derivations of tier 1. `ink`, `surface`, `bg`, and `line` were already role-named and are unchanged. The accents split into **roles** — `--color-accent` (was `gold`), `--color-danger` (was `ember`), `--color-success` (was `positive`) — and a **categorical set** of **8 derived `--color-tone-*`** (plus `-soft`), replacing `sea` and `astra`. "Gilded" becomes an `accent-sheen` **material** whose stops, glow, and on-colour derive from the accent by default and remain individually overridable.
- **Eight tones, not twelve, and the reason is structural.** The accent sits _between_ danger and success on the hue circle (−43° and +58.5° from it), so excluding both does not take two bites out of a wheel — the exclusions merge into one continuous forbidden zone, leaving a single ~161° arc running cyan → violet → magenta. Every tone is therefore a cool colour, in the least hue-efficient part of OKLCH (15° buys ΔE00 ≈5 there against ≈8 in the excluded warm region). Twelve tones in that arc land at min pairwise ΔE00 **4.8**; eight reach 10.8. The exclusion is not optional — twelve on the full circle put one tone ΔE00 1.6 from `--color-success` and one exactly on the accent — and its _width_ barely matters (15→20 units costs one tone); having one at all halves the palette.
- **Tones are assigned to Entity Types deterministically by hashing the type id**, with an explicit override, so two plugins cannot silently collide on the same tone.
- **`-soft` is emphasis, not identity.** At α 0.14 the tone fills land within ΔE00 1.4 of each other at N=8 (0.9 at N=12) — below a just-noticeable difference. The chip's category signal is its **text and border** colour; the fill is decoration. `chip.component.ts` changes accordingly.
- **Categorical colour is backed by a non-colour channel.** The exclusion arc is the canonical deuteranope confusion line, and no hue-rotation set above ~4 tones survives it — max-min ΔE00 for a deuteranope is 5.6 at four tones. Chasing hue separation is the wrong lever, so chips carry the Entity Type's `icon` (already on `TypeDefinition`) alongside the label. Colour then does decoration's job honestly rather than being identity that quietly fails for ~8% of male readers.
- **Tier 3 — a plugin's own vocabulary**, declared in that plugin's lib. The boundary is _what a token means_, not who happens to use it: tier 2 is a concept the design system names, tier 3 is a plugin's private one. So `canvas-*` and `ink-stroke` stay in core despite having only plugin consumers today — an infinite pan/zoom field and a legibility halo are design-system concepts — while the ten hexmap-specific tokens (`hex-line`, `feature-ink`, `label-ink`, `name-ink`, and the six live `terrain-*`) move into `plugin-hexmap-web`. A rule keyed on meaning survives a new plugin; one keyed on usage would have put `canvas-*` inside hexmap before board existed, then required moving it back.
- **Terrain colours leave the public contract entirely** with that move. A per-World _terrain set_ — a seventh terrain, not merely a recoloured one — is a schema change to the `terrainIdSchema` enum and a separate feature; scoping terrain out now stops this one being sold as that one. `--color-terrain-marsh` is deleted, with its styleguide entry.
- **Derivation runs in CSS.** `oklch(from …)` for the ramps, `color-mix()` for soft variants, `contrast-color()` for on-colours — the last re-tinted through `oklch(from contrast-color(…) l <c> <h>)` so an on-colour is never pure black or white, which ADR-0006's warm through-line forbids. All three are Baseline across the evergreen targets; `if()` and `@function` are not, and are not used.
- **Every public token is `@property`-registered** with a `syntax` and an `initial-value`. This is load-bearing correctness, not hygiene: once `--color-*` hold expressions rather than hexes, an _unregistered_ property returns the raw string `oklch(from #9a6a16 max(l,.713) …)` from `getPropertyValue`, and three call sites hand that straight to a 2D canvas context (`map-renderer.ts:211`, `board-canvas.component.ts:342`, `graph-palette.ts:12`). Canvas `fillStyle` probably parses relative colour syntax in current engines, but where it doesn't it silently falls back to a hard-coded hex. Registration makes the value resolve, and it is also what makes the contrast reporting in ADR-0076 possible and the type guard it relies on. (**Amended in implementation (#362, #365):** "every" overstates what the platform allows. `@property` has no syntax component for a shadow or a font stack, so the five `--shadow-*` and four `--font-*` are declared public but unregistered; and an `initial-value` must be computationally independent, which `rem` is not, so the nine `--text-*` and the `--tracking-*` are unregistered too — registering them would have frozen their relative units against `:root` and moved headings. None of the exceptions is read by a Canvas renderer, which is the risk the rule exists to close. The manifest carries `unregistered: true` to make the exception declared rather than incidental.)
- **Hexly's own Solar and Astral go through the derivation path.** They are generated from anchors, not hand-written beside the formula. A derivation exercised only by other people's themes is a code path nobody on this project ever looks at. All 35 fitted tokens land at ΔE00 ≤ 2.91 in both schemes (70/70 under 3, mean 0.89), so the repaint is a perceptible-side-by-side shift on a handful of tokens and invisible on most.
- **A token that needs an affine knob is an exception, not a derivation.** Where one can be re-parented to become a genuine single-coefficient derivation, it is (`overlay` off the page anchor, `on-gilded` via `contrast-color()`, the shadows off one ink anchor once their geometry is unified). Whatever resists becomes a **named literal**, alongside `canvas-glow` — which is a literal outright, because Solar's field glow is a warm highlight of its own paper while Astral's is a different-hue light source on indigo, a 5× difference in lift that is two design ideas rather than one parameterised one. A formula that can hit any two targets tells a World Owner it will generalise and it will not; that is a worse failure than an honest literal, wearing a disguise. (**Amended in implementation (#369):** `canvas-glow` is no longer the only one. The hex map's `--color-terrain-mountain` is a second named literal on the same precedent — warm tan by day and violet by night is a change of _hue_ that the field's own shift does not account for, so no one pigment sits at both ends of the wash the other five terrains ride. See the spec's §3 amendment.)
- **Two behavioural changes fall out of the fit and are taken deliberately.** Solar's `line` and `line-strong` go **opaque → translucent** so the ramp is one rule in both schemes (Astral's already is); Solar's rules become backdrop-sensitive as a result, matching at `surface` and diverging by up to ΔE00 11.5 over `bg`. And the shadow **geometry** is unified — today's Astral/Solar offset ratios are 1.0, 1.5 and 1.375, which no single scale knob can be, and the divergence reads as drift rather than intent. Only shadow colour and alpha re-theme.
- **A manifest is the single source of the contract.** It declares each public token's tier, type, and default, and generates the `@property` block, the zod schema at the write choke point, the lint allowlist, the `DesignToken` union type, and the theme editor's controls. Five things that must agree on "what is a themeable token of what type" and will drift the moment they are maintained separately.
- **`no-unknown-design-token` reads the manifest** instead of grepping the CSS files, and gains tier awareness: a component referencing `--palette-*`, or another plugin's tier-3 token, is an error.
- **Vocabulary.** The day/night axis is a **ColorScheme** (`Solar` | `Astral`), not a "theme" — see CONTEXT.md. `data-theme` becomes `data-color-scheme`, `ThemeService` becomes `ColorSchemeService`, and the persisted preference field renames with them.

## Consequences

- **~331 accent-family call sites rename**; `ink` (391), `surface` (143), and `line` (135) do not. The rename is mechanical and belongs in its own no-behaviour-change commit, so review is of a codemod rather than of 300 diffs and `git blame` takes one hop to clear it.
- **71 token references are bare strings**, not `var()` — `graphColorToken: '--color-astra'`, `terrainPalette`'s `fill:`, and a pile of spec fixtures. `no-unknown-design-token` matches only `var(--…)` and structurally cannot see them; they compile clean and go silently stale. The `DesignToken` union exists for exactly this, and typing `graphColorToken: DesignToken` is what closes the hole. `graph-palette.ts`'s hardcoded hex fallbacks have the same failure mode and no such guard.
- **The tier-3 move has a prerequisite, and measuring it corrected the diagnosis.** `@source` in `apps/web/src/styles.css` globbed only `apps/web`, `web-ui`, `web-core`, and `web-entity` — **no plugin lib was declared**. The plugin templates that use theme utilities (`bg-gold-soft`, `text-gold-strong`, `border-line`) were nonetheless generated, but by Tailwind's **automatic source detection**, which walks the whole workspace from the build's cwd: it also read `docs/`, `.claude/`, and an ESLint fixture, and emitted 29 rules no template applies. Coverage nothing declares is coverage nothing guarantees. #359 closes it with `@import 'tailwindcss' source(none)` plus globs naming every browser library, so the tier-3 move lands on a scan set that is declared rather than incidental.
- **Devtools stays legible and tier-2 overrides are nearly free** — an inline custom property on `<html>` beats the stylesheet's derivation, which is the mechanism ADR-0076 leans on. Gamut mapping turned out to be a non-issue for the chrome tokens: exactly one derived value leaves sRGB (Solar `surface-raised`, by 0.51% of one channel), well below where engines diverge. It is a live consideration for the tones, two of which are gamut-mapped, and for any future anchor with more chroma than today's, since the ramp expressions extrapolate.
- **The eight tones use two lightness rows, and those rows invert their visual weight between ColorSchemes.** An `l * 0.8` tone is darker, so it reads heavier on Solar's ivory and lighter on Astral's indigo — a category's emphasis ordering flips when a reader toggles theme. A seven-tone iso-lightness set (`calc(l * 0.9)`) has no such flip and is a one-line swap if consistent ordering ever matters more than the eighth tone.
- **The dogfooding condition needs a net that does not exist.** `apps/web-e2e` has 57 specs and zero visual or snapshot assertions. The right net is a **token snapshot test** — read `getComputedStyle(document.documentElement)` for every registered token in both ColorSchemes and assert against a committed table. It catches formula drift precisely, and it exercises the same resolved-value path the contrast reporter depends on, so the test and the mechanism are the same thing.
- **`ChipTone` changes shape** from `'gold' | 'sea' | 'astra'` to the role/tone vocabulary (11 call sites), and `terrainPalette` in `hex-map.ts` wants renaming to clear the third "palette" collision — cosmetic, and it rides along with the tier-3 move it is already part of.
- **`identity.md` loses some poetry.** The evocative names move down to tier 1, where `--palette-*` can be gold and sea and astral honestly, because a hue name for a hue is not a lie.
