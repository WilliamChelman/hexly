# The Local Graph Panel: a server-bounded neighbourhood read, drawn by the World Graph's renderer

The **References** Panel answers "what links here" as a list of names; readers also want the _shape_ those names make, without leaving the Entity for the World Graph page and hunting for the node they came from. So the **Local Graph** joins References and Details as a universal Dock Panel (ADR-0067): the same node-link drawing, centred on the open Entity, bounded to its neighbourhood by a **depth** the reader sets. The projection is the World Graph's (ADR-0046) — one read shape, one renderer, one set of colours — narrowed, never reinvented.

## Decisions & consequences

- **The bound is the server's, not a filter over the World.** `GET /entities/:id/graph?depth=N` walks the neighbourhood and returns only it, so the payload is proportional to what is drawn rather than to the World — this Panel opens on every Entity page, where the whole-World payload the graph _page_ holds would be an absurd price. Consequence: changing depth is a refetch, keyed with `(id, seq)` like References; only the ephemeral decor reveal filters client-side.
- **Depth is clamped, not refused**, at a ceiling of 5 hops (a hop multiplies the payload by the average degree). Past it, the World Graph page is the right surface. A reader asking for more than exists wants everything, as with a list `limit`.
- **Hops are undirected and semantic-only** (ADR-0069). Undirected because "this Entity's neighbourhood" is not a question about which end authored the link. Semantic-only because the Local Graph is a relation surface: a Thumbnail or a prose image must not widen the picture. Decor edges _between_ included nodes are still returned, flagged, for the reveal — so revealing decor annotates the drawing and never grows it. Consequence: every node has a semantic path to the centre, so the drawing is connected by construction and needs **no orphans filter**, unlike the page.
- **The walk crosses the graph the viewer sees.** Both endpoints are access-filtered before the walk, so an unreadable Entity is not a bridge: it is absent as a node, and so is everything only reachable through it. Neither the Panel nor the endpoint is offered on a Public Link page, whose scope is one Entity.
- **Depth persists per user, the decor reveal does not.** How far out a reader likes to look is a habit worth remembering across Entities and sessions; a peek at presentation wiring is not (ADR-0069).
- **The centre is pinned.** It takes no physics force (cosmos.gl's `setPinnedPoints`), seeded at the middle of the space, so the layout arranges _around_ it and the Entity the drawing is about stays where the reader looked for it; it still acts on its neighbours, and stays draggable, so a reader may always move it.
- **The camera judges its framing rather than tracking the layout.** One fit cannot hold a drawing that contracts, expands and drifts for ~10 s of cooling, and a panel-sized box has no slack to absorb it — the drawing sailed out of view. But re-fitting on a timer is worse: chasing a layout that moves every frame makes the whole graph bounce, which is far more uncomfortable than a graph sitting slightly off-centre. So the framing is _tested_ on a slow cadence and corrected only when it is genuinely wrong — the drawing has left the viewport, or contracted into less than half of it — and the camera stops judging for good at the reader's first pan, zoom or drag. Measured on a 17-Entity World: 7 corrections instead of ~48, all inside the first reorganising seconds, then perfectly still. Lives in the shared renderer, so the World Graph page gains it too (it pins no centre — a World is about no one Entity).
- **The renderer moves into `web-entity`.** The cosmos.gl canvas and its label/payload utilities were page-local; both surfaces must draw the same picture, so they now live beside the Panel that is core (ADR-0067) and read types through `ENTITY_TYPES` (ADR-0048) rather than `apps/web`'s registry. It gained a `center` input — the centre draws larger than its degree alone earns it, since at depth 1 every other node looks alike. Its node/edge SQL likewise moved to a shared read both the World-wide and Entity-centred services call.

## Considered Options

- **Fetch the whole World Graph and walk it client-side** — rejected: instant depth flips, but every Entity page open pays for the whole World to render a 320px panel, and the Panel is remembered open across navigation. The walk is cheap; the transfer is not.
- **A recursive-CTE walk in SQL** — rejected for now: at one embedded SQLite World the World-wide reads are already cheap, and a second definition of "what an edge is" (asset-hash resolution, decor, both-endpoint access) is a real cost. The seam is the service, so this can change without touching the client.
- **Walk decor edges too, then prune client-side when decor is hidden** — rejected: pruning leaves nodes floating detached from the centre, or needs a second "connected to the centre" pass whose result depends on how far the fetched payload happened to reach. Not walking decor makes connectedness a property of the read.
- **A "local graph" mode on the World Graph page instead of a Panel** — rejected: the value is reading the shape _while_ reading the Entity. A mode on another page is the navigation this removes.
