# The Compendium is a sealed, Instance-wide Container, entered only by Adoption

The Draw Steel **Importer** (ADR-0060/0061) drops a whole bestiary into a World, where it drowns the **Entity Browser**, the **Facets**, the **World Graph**, and the World's Entity count in content nobody authored — while a hand-written NPC that happens to carry `draw-steel.type.monster` must stay an ordinary Entity, so the partition can be neither the **Entity Type** nor anything the author sets. We make it **location**: a **Compendium** is a kind of **Container** (ADR-0078), one per pack, Instance-wide, installed and reimported by the operator rather than by a World Owner. An Entity is a **Compendium Entry** because of where it lives, and nothing else — which means every World-scoped read already excludes it for free, with no new predicate on six read paths and no boolean anyone can forge in vault frontmatter.

Compendium Entries are **Sealed**: read-only to everyone, and no Entity outside the Compendium may link to one. The line the seal is drawn on is **find versus link** — _link-target_ surfaces (the `@` picker, the **Entity Link** Field picker, the Board **Embed** picker, the **Vault** import's wikilink resolution) never return a Compendium Entry, while _navigation_ surfaces (the **Command Palette**, full-text search, the entry's own read-only Entity page and its shareable URL) do, ranked below authored Entities.

The one way compendium content enters a world is **Adoption**: a copy into a World as an ordinary editable Entity, same name, same Types, same values, stripped of `hexly.source` and carrying no record of origin. Browsing and adopting live at `/w/:worldId/compendium` — the World in the URL naming the adoption target, not the content's home — as an Entity Browser preset unioning every installed pack behind a **Pack** facet; installing, reimporting, and removing packs is an operator surface in the admin area. The nav rail's **Library** becomes **Entities**, because "Library" leans reference and would have read as the Compendium's word, not the author's.

## Considered Options

- **Compendium-ness as an Entity Type, or as a `hiddenFromDefaultListing`-style flag on one.** Rejected first and hardest: it exiles a correctly-modelled hand-written NPC-who-is-a-monster from its author's own Browser, punishing accurate modelling.
- **Compendium-ness as "has an Import Source."** Rejected: ADR-0060 names the **Vault** import as a future user of the Importer seam, and the day it moves there this rule reclassifies every note the user ever wrote in Obsidian as reference material.
- **Compendium-ness as an Entity-level boolean the document carries** (so it survives a vault round-trip). Rejected: a boolean in frontmatter is settable by hand, which restores the arbitrary user flag we had just ruled out, and it needs a fresh exclusion predicate on every World-scoped read. The Container answers both — round-trip fidelity comes from the import's _destination_, not from a key.
- **A per-World compendium, partitioned in place.** This was the working assumption for most of the design and it lost to the seal: the objections to Instance-wide were all cross-World Entity Links, Rights, graph edges and References, and sealing removes every one of them. Per-World would also duplicate a pack per World and require the exclusions the Container gives away.
- **Unsealed Compendium Entries, linkable in place.** Rejected once **Adoption** existed: linkability forces reimport's delete path to dangle user links (the exact hazard ADR-0060's identity-preserving upsert was built to dodge), and it splits a world's references between "points at the shelf" and "points at my copy." Sealing also matches Foundry's compendium packs, which users arrive already understanding — you drag an entry _out_ to use it.
- **Enforcing the seal at the write choke point** (rejecting, or silently dropping, a write whose document links a Compendium Entry). Rejected: the rule lands on _prose_, so one inline mention in a long **Content** field would fail the whole save — and with ADR-0026's debounced autosave that is a data-loss vector, not a validation message. It also cuts against ADR-0074, which already decided a document-level shortcoming prompts rather than gates. ADR-0068's choke-point precedent governs a discrete structural act (attaching a **System-managed** type), which this is not. Dropping the edge silently instead was rejected for producing links that navigate fine yet never appear in References, with nothing on screen explaining why.
- **Recording an origin on an adopted Entity** (`hexly.adoptedFrom`). Rejected: a second provenance concept every future surface must learn — the write choke point, **Reindex**, the Vault export, the graph — bought for an "already adopted" indicator and a re-sync that ADR-0060 has already disclaimed ("its job is not chasing upstream").
- **Excluding Compendium Entries from search and the Palette too** (a harder seal). Rejected: it makes the Palette lie about what the Instance holds, and makes a monster's URL unshareable. A user who half-remembers a name should find it without first knowing which side of the wall it is on.

## Consequences

- **Adopted copies are frozen at the revision adopted, permanently.** With no origin record there is no re-sync and no staleness warning; a user can accumulate sixty copies of an outdated pack and nothing will ever say so. This is the accepted price of one provenance concept.
- **There is no "already adopted" indicator**, so the same monster can be adopted repeatedly. Self-correcting — the duplicates are visible in Entities — but a real papercut, accepted knowingly.
- **Adoption is curation, and the Entities browser refills accordingly.** A campaign using sixty monsters ends with sixty adopted Entities. That is the intended reading: a World holds what its authors chose, not what was available.
- **ADR-0060's identity-preserving upsert loses half its stated rationale.** "Inbound links and grants survive" cannot apply where no inbound link may exist; id preservation now serves only the reconcile's own diff. The mechanism stays correct, its justification shrinks.
- **A World Owner on a shared Instance can no longer install a bestiary** — it is an operator action, consistent with ADR-0052 making plugin enablement Instance-wide. On the **Desktop App** and any **Sole User** instance the distinction is invisible.
- **No upgrade migration is needed.** The Draw Steel importer landed after `v0.1.2` and is in no tagged release, so no deployed Instance has ever run it. Pre-existing links are likewise left alone: the seal applies to what is created from here.
- **The seal is held by discovery, not by an invariant.** A link forged through the API against a known id will render and may dangle on reimport. Accepted: a rare forged link that behaves like a link beats a class of links that quietly half-exist.
- **A Compendium can only be reached through its own browse and by name.** Combined with ADR-0078's container scoping, this retires several questions rather than answering them: there are no compendium nodes in the **World Graph**, no compendium rows in **References** or the **Local Graph**, and a World's **Vault** export cannot contain compendium content because it is not in the World.
- **Attribution renders where the content is read.** ADR-0061 satisfies the Creator License with a `NOTICE.md` in the plugin source, invisible to the person reading the monsters; the `compendiums` satellite carries publisher, license, and notice so the pack's own page states its terms — and a future user-published pack has somewhere to state its own.
- Deliberately deferred, as decisions rather than gaps: publishing a **World** as a Compendium (exporting a Container as a vault), re-syncing adopted copies against a newer pack, and the "already adopted" indicator.

## Amendment: the no-link half of the seal becomes the **Mount** scope (ADR-0080)

"Unsealed Compendium Entries, linkable in place" is reinstated, scoped. ADR-0080 replaces "never a link target" with _a link target must be in the linking Container or one it **Mounts**_ — a property of the pointing World rather than of the entry, so **Sealed** now means read-only and nothing else, and a World with no Mounts behaves exactly as this ADR specifies. The two objections recorded above are accepted rather than answered: reimport's delete path will dangle user links (warned by a count at unmount, Container delete and pack removal, never refused), and a World's references do split between the shelf and an adopted copy.

That split was in any case already being minted here. **Adoption** copies an entry's values verbatim, outbound links included, so an adopted Marauder Goblin arrives in a World pointing at the pack's Queen Goblin — the cross-container link this ADR forbids, produced by the one act it endorses, asserted by its own test (`compendium-adoption.controller.spec.ts:155`). "The seal is held by discovery, not by an invariant" was truer than intended.

Adoption survives unchanged as the _fork_ door — you adopt when you mean to change the thing — and the **Compendium browse** generalises into the **Library**, faceted by Container, with a pack one Mount among several. That completes this ADR's retirement of "Library" rather than reversing it: the word was retired for leaning _reference_, and it now names the reference surface.
