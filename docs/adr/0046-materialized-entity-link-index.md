# Materialize Entity Links into a derived, source-access-filtered edge index

Entity Links live *inline* — an `entityLink` node inside an Entity's ProseMirror Content, and a bare `entityId` on a Hex Map's Hexes, Features, and Regions — with no record of who links to whom. Two surfaces need the reverse and the whole: an Entity page's *References* / *Referenced by*, and the **World Graph**. Rather than walk every Entity's `document` on read, a single derived table records one edge per distinct `(sourceEntityId, targetKind, targetId, descriptor)`, rebuilt wholesale on every save at the `EntityWrites` choke point, and every read that exposes an edge filters it by the viewer's access to its **source** Entity. The table is an index, never a source of truth — droppable and recomputable from the documents at any time.

## What the table holds

- **Polymorphic target.** `targetKind` is `entity | asset`; `targetId` holds an `entityId` or an Asset `hash`. One table, because both surfaces union the two and a future `map → asset` link (Maps carry no Assets *today*) slots in with no schema change.
- **No FK on `targetId`.** Targets are deliberately dangling-allowed (a link to a missing or `private` Entity is a valid document), so the target column is unconstrained text resolved opportunistically on read — never a referential constraint.
- **`sourceEntityId` FK → `entities.id`, `ON DELETE CASCADE`.** Deleting an Entity drops its outbound edges with it.
- **`worldId`** is denormalized from the source, so the World Graph's edge fetch is one indexed `WHERE worldId = ? AND targetKind = 'entity'` — the same denormalization `entities` and `assets` already carry.
- **`descriptor`** (the Link Descriptor) is nullable and set only on `content → entity` edges; it distinguishes two rows to the same target ("spouse" *and* "rival" between the same pair are two edges, not one).

## The access rule is the point

The rows are raw truth — A → B regardless of who may see A or B. Confidentiality lives entirely in the read:

- **Inbound** (*Referenced by* on B's page) is filtered by the viewer's access to the **source**. B's page shows an edge A → B only if the viewer can read A. Otherwise a `private` "Secret Cabal Roster" that links a `shared` town would leak its name and existence to anyone who can reach the town — which `private` (absolute; no World-Owner or Admin override) forbids.
- **World Graph** applies the same filter to *both* endpoints: an edge appears only when the viewer can read source *and* target, and a node appears only when readable. Assets are never nodes. Orphan Entities (no edges) still appear, sourced from the accessible-entities query rather than the edge table — so the graph's node set is the readable Entities of the World, and the edge table only supplies the connections.
- **Outbound** (*References*) needs no hiding: a link to an unreadable or deleted target renders as the existing non-navigable dangling label.

The filter is the ordinary per-viewer accessible-entities filter used everywhere else, never cached across viewers.

## Considered Options

- **Scan documents on read** — rejected. Computing *Referenced by* or the World Graph would walk every Entity's `document` JSON (via the `visit` seam) on every request; it cannot be indexed, and the Graph would scan the whole World. The write path already parses the Content once to derive `contentText` and descriptors — harvesting edges in the same pass is nearly free, and turns an O(world) read into an indexed lookup.
- **Stay inline, compute in the client** — rejected. The client only holds the Entity it opened, so it cannot know who links *to* it, and access-filtering a graph client-side would require shipping unreadable Entities to filter them out — the leak the access rule exists to prevent.
- **Two tables (entity edges, asset refs)** — rejected. The columns don't diverge enough to justify doubling the write path and the query surface; a `targetKind` discriminator costs one column.
- **Record `sourceKind` (content vs map)** — rejected. No surface distinguishes a prose mention from a map placement, so it would be dead data; without it, a plain content link and a map placement of the same target simply collapse to one edge. Added back the day a surface renders the distinction.
- **FK the target / validate on write** — rejected. It contradicts the dangling-allowed invariant and would reject valid documents (imports, forward references, links to later-deleted Entities).

## Consequences

- **One more derivation at the choke point.** `EntityWrites.derive(content)` already returned `contentText` and descriptors (ADR-0045); it now takes the whole `EntityBody` — a Hex Map's links live on its Hexes, Features, and Regions, not only in its prose — and gains the edge set, harvested from the Content snapshot (`entityLink` → entity, `image` → asset) and the map payload (`hex`/`feature`/`region` `.entityId` → entity). The write `DELETE`s the source's rows and re-`INSERT`s — wholesale replace, no diffing, mirroring `replaceDescriptors()`. An edge cannot land without a save, and a save cannot skip it.

- **The Link Descriptor vocabulary becomes a projection of the edge set**, and `harvestDescriptors` is deleted. Only a `content → entity` edge carries a descriptor, so the non-null descriptors of the harvest *are* the descriptors the Content uses, and `derive` runs one traversal instead of two. This revises ADR-0045's "`derive` … is the only caller of `extractText` and `harvestDescriptors`": the second callee is now `harvestEdges`. The guard is behavioural, in `EntityWrites`' descriptor specs, not in a unit test of the deleted function.

  The projection narrows the vocabulary in exactly one case: an `entityLink` with no `entityId` mints no edge, so a descriptor stranded on a targetless link no longer joins the vocabulary. That is the better rule — a descriptor characterises a relationship *to* something — and it is unreachable in practice: the editor's picker always sets `entityId`, and the one path that mints a targetless link (an unresolved import wikilink) sets `descriptor: null` alongside it.

- **An edge stores its descriptor as authored; only the *vocabulary* folds case.** The edge index mirrors a Content link, and the link renders its raw `descriptor` attr in the prose. Storing the folded form would put `Capital Of` on the inline chip and `capital of` in the References panel — two spellings of one descriptor, side by side on one screen. So `descriptorSchema` trims and rejects blanks but preserves case, the dedup **key** folds (`"Spouse"` and `"spouse"` name one relationship, hence one edge, keeping the first spelling authored), and `descriptorsSchema` — the Tag-shaped normalizer — folds where the `::` vocabulary is built. Folding is a property of a vocabulary, not of a descriptor.

- **A derived-index rebuild is batched under SQLite's bound-parameter limit.** `SQLITE_MAX_VARIABLE_NUMBER` is 32766 and an edge row binds five parameters, so one `INSERT … VALUES` hard-fails past 6553 edges with "too many SQL variables" — rolling the save back and leaving the document *permanently unsavable*. A Hex Map naming that many Entities across its Hexes, Features, and Regions sits inside the "low thousands of nodes" a World is expected to hold, so `replaceEdges` (and `replaceDescriptors` with it) chunks its `VALUES` list.

- **The harvest is format-guarded like `extractText`.** A Content snapshot is walked only under a `tiptap-*` format tag this build knows; the map payload is format-independent, so a Hex Map's placements survive a Content format it cannot read. `harvestDescriptors` carried this guard and the edge harvest inherits it — losing it would have let an unreadable snapshot mint edges from nodes it cannot interpret.
- **Population is a Superadmin Reindex, not a backfill.** Nothing is in production to migrate, so existing Entities gain their edges by recomputation: a Superadmin-gated route walks every Entity and re-runs `derive()` + replace, rebuilding `contentText`/FTS, descriptors, and edges together. This is the operational form of "droppable and recomputable" above, and it generalizes past this feature — any future document-derivation is applied retroactively by the same button, safe to re-run because the document is the source of truth. It lives with Superadmin (the repair tier), *not* the Instance Admin surface, which deliberately reaches no Entity.
- **One endpoint, both directions.** `GET /entities/:id/references` returns `{ references, referencedBy }` — one round trip and one resolution of the viewer's access context, because the Entity page always shows both. It is *not* folded into `EntityDetail`: every entity fetch, and every save response, would then pay the inbound join for two fields the editor never reads. The route is `references`, not `links`, because `:id/link` is already the Entity's Public Link.

- **The References panel shares the Outline's dock**, as a second entry on a rail beside one panel slot. Which panel shows is a single discriminant on a page-owned `RightDock` — the note-view peer of `HexMapStore.rightPanel`, and modelled that way on purpose: a boolean per panel would let a second `toggle()` caller open both at once, rendering one behind the other while both toggle buttons read as active. One signal makes that unrepresentable, and gives the reading column one thing to reserve room for (either panel overlaps prose if it does not reflow).

  It ships on the Content-body views (a Note, and a Hex Map on its Note view), which is where a `note` lives and one toggle from where a map does. The Map view keeps its own dock, whose panel selection `HexMapStore` owns and re-opens on every selection change; putting References in that slot would have it closed out from under the reader by a map click, and the whole map dock sits behind `writable()`, so a read-only viewer would never reach it. Merging the two docks is the upgrade path, and the price of surfacing References on the Map view.

- **The panel's freshness has a ceiling, and it is the inbound half.** The fetch is keyed on the open Entity's `(id, seq)`, but only *References* is a function of that Entity's document. *Referenced by* changes when some **other** Entity saves a link here, bumping that Entity's `seq` and never this one's; an outbound target's rename moves only the target's. So an open panel refreshes on reopen, on navigation, and on this Entity's own saves — not on either of those. Live-following it would need a per-target interest index the nudge bus deliberately does not keep (ADR-0044). The store says so where a reader will find it, rather than implying `seq` buys more than it does.

- **Asset edges are stored but surface-less for now** — preparatory groundwork for Asset orphan detection / GC, harvested in the same content walk. No Entity-page or Graph surface consumes them yet. The `image` `src` is parsed back to its Asset `hash` through `assetHashFromUrl`, the inverse of the `assetUrl` builder the Assets service mints with — one definition of the `/assets/<worldId>/<hash>.<ext>` shape, so the two cannot drift. An external `https:` or `data:` image references no Asset and is no edge.
- **Stale inbound rows to a deleted target are not swept eagerly.** Deleting B cascades B's *outbound* rows, but `A → B` rows keyed by A remain; the read drops them (target no longer resolves) and A's next save rewrites them. A background sweep is the upgrade path if the dead rows ever matter.
- **The World Graph ships as a full-World payload**, client-rendered, no windowing — human-authored worlds sit in the low thousands of nodes. The ceiling, marked at the endpoint, is a node cap plus a single-Entity-neighbourhood mode if a World ever grows past what a client force-graph handles.
- **Names are never stored on an edge** — only ids. A target's rename needs no edge rewrite; *References* / *Referenced by* resolve the current name from `entities` live, and the inline `label` snapshot remains the dangling-only fallback in Content.
